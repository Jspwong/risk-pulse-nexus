这篇文档是给第一次接触这个项目的人看的。

如果你不想先看架构细节，只想快速明白这套系统是怎么跑起来的，可以先看这里。

## 一句话理解这个项目

这个项目做的事情很简单：

> 把外部世界正在发生的新闻、风险和信号，整理成企业能看懂、能行动的提示。

它不是只显示新闻，而是尽量回答三个问题：

- 发生了什么
- 会影响企业什么
- 现在应该怎么做

## 整体流程

你可以把整个项目理解成一条流水线：

```text
外部数据源
  -> 数据抓取和清洗
  -> 风险识别和分类
  -> 业务影响计算
  -> 前端页面展示
  -> 用户查看、筛选、响应
```

每一步都有自己的作用，但目标都只有一个：把复杂的信息变成清楚的行动建议。

## 这套系统怎么工作

### 1. 先从外部世界拿数据

系统会从很多来源拿信息，比如新闻、地缘事件、供应链、市场数据、天气、航运和航空信息。

这些数据一开始都很杂：有标题、有正文、有时间、有地点，也可能有噪音和重复内容。

### 2. 再把原始信息整理成“风险事件”

项目会把杂乱的信息整理成结构化的风险事件。

简单说，就是把一条新闻变成这样的问题答案：

- 这条信息属于哪个风险方向
- 影响哪个地区、行业或业务线
- 严重程度大不大
- 值不值得提醒用户

这样做的好处是，前端不需要自己读新闻内容，只要直接看整理好的结果。

### 3. 再判断会影响企业哪里

系统不会只停留在“这是一条新闻”，还会继续判断：

- 会影响哪个部门
- 会影响哪条业务线
- 会不会影响交付、成本、利润或合规
- 是否需要马上处理

这一步很重要，因为企业真正关心的不是新闻本身，而是新闻会不会影响业务。

### 4. 再算出可理解的结果

系统会把影响进一步转换成比较容易理解的指标，比如：

- 暴露金额
- 预估损失
- 可减少的损失
- 系统成本
- 净收益
- ROI

这样用户看到的不是一堆抽象标签，而是更接近业务语言的结果。

### 5. 最后在页面里展示出来

前端会把这些结果做成卡片、表格、地图和面板。

用户可以：

- 看当前风险列表
- 看某条风险的详细说明
- 看它影响了哪些业务
- 看它值不值得投入处理
- 继续追踪后续变化

## 项目里主要有哪几部分

### 浏览器前端

这是用户直接打开后看到的页面。

它负责：

- 展示地图、卡片和图表
- 接收后台整理好的数据
- 处理点击、筛选、展开等交互
- 把复杂信息变成可读界面

### 数据服务层

这一层负责把外部数据变成可用结果。

它做的事包括：

- 请求外部 API
- 处理失败和重试
- 缓存结果，减少重复请求
- 把分散的数据统一成前端能用的格式

### 风险与规则层

这一层负责“判断”和“计算”。

它会决定：

- 哪些信号要被当成风险
- 风险应该归到哪个类别
- 哪些事件需要优先提醒
- ROI 和损失怎么算

### AI / 代理能力

项目里也有 AI 参与，但它不是直接替代业务逻辑，而是帮忙做识别、归类和解释。

更直白一点说，AI 更像“助手”，主要负责：

- 帮你读大量内容
- 帮你找重点
- 帮你补说明
- 帮你把复杂信息说清楚

最终结果还是要经过固定逻辑和代码计算，保证输出稳定。

## 技术实现怎么落地

如果你想知道“这套东西到底是怎么写出来的”，可以把它理解成下面这条技术链：

```text
浏览器入口 -> 页面初始化 -> 面板创建 -> 数据加载 -> 风险计算 -> 页面渲染
```

### 1. 浏览器入口先把应用跑起来

项目真正的启动入口在 `src/main.ts`，它负责把页面环境先准备好，比如主题、错误处理、运行时配置等。

然后 `src/App.ts` 开始主流程。它不是一下子把所有东西都拉起来，而是分阶段做：

- 先准备存储、语言和页面状态
- 再挂载地图、搜索和事件处理
- 然后开始数据加载
- 最后把刷新和后续更新跑起来

这样做的好处是，页面不会因为某一个数据源慢，就整个卡住。

### 2. 面板是先注册，再显示

面板不是“写在页面里等着显示”，而是先在 `src/app/panel-layout.ts` 里注册好。

比如企业风控相关的两个面板：

- `enterprise-risk`：主面板，负责展示风险、ROI、任务和说明
- `enterprise-risk-events`：事件列表面板，负责展示每一条风险事件

这两个面板是联动的：你在事件列表里点一条事件，主面板会跟着切到对应内容。

### 3. 数据是按需加载，不是一次全塞进来

真正拉数据的地方主要在 `src/app/data-loader.ts`。

它的思路很朴素：

- 先看当前页面需要哪些数据
- 只加载当前可见或附近会用到的内容
- 同一类请求加保护，避免重复发很多次
- 某个来源失败时，不让整个页面一起坏掉

所以这个项目看起来像“实时大屏”，但实现上并不是所有接口同时狂打，而是有节奏地分批拿数据。

### 4. 风险计算在服务层完成

企业风控的核心计算在 `src/services/enterprise-risk.ts`。

这一层负责把原始事件变成可计算的结果，比如：

- 这个风险属于哪个轴
- 影响哪些业务线
- 预计损失是多少
- 系统能减少多少损失
- 最后 ROI 是正还是负

它会输出几个最关键的数字：

- `expectedLossUsd`
- `expectedSavingUsd`
- `mitigationCostUsd`
- `netSavingUsd`
- `compositeRoiPct`

如果有 Qwen 参与，它的作用也只是提供假设和解释，不是直接替代最终计算。真正的结果还是由固定公式算出来，这样更稳定，也更容易测试。

### 5. 页面只是把结果讲清楚

最后，`src/components/EnterpriseRiskPanel.ts` 和 `src/components/EnterpriseRiskEventListPanel.ts` 负责把结果变成用户看得懂的页面。

主面板会展示：

- 哪些风险正在活跃
- 每个风险的概率、暴露、损失、节省、成本和 ROI
- 哪些任务已经生成
- 沙盘里不同假设下会发生什么

所以你可以把前端理解成“展示层”，把服务层理解成“算数层”，把数据加载层理解成“搬运层”。

## 一次完整的技术流程

把上面的内容串起来，就是这样：

1. 用户打开页面，`src/main.ts` 启动应用。
2. `src/App.ts` 按阶段初始化页面。
3. `src/app/panel-layout.ts` 把企业风控面板挂上去。
4. `src/app/data-loader.ts` 从外部来源拉取新闻和业务数据。
5. `src/services/enterprise-risk.ts` 把事件整理成风险结果并计算 ROI。
6. `src/components/EnterpriseRiskPanel.ts` 把结果画成卡片和表格。
7. 用户点击事件列表，主面板跟着更新。

如果一句话概括，就是：

**启动应用 -> 拉取数据 -> 算出影响 -> 渲染页面 -> 让用户做决定**

## 一次完整流程长什么样

你可以把它想成一次从“外部消息”到“企业动作”的过程：

1. 外部新闻或数据出现
2. 系统抓取这条信息
3. 系统判断它是不是风险
4. 系统把风险归类
5. 系统计算影响范围
6. 系统生成可读的提示和数字
7. 用户在前端看到结果
8. 用户根据提示做下一步判断

如果信息持续变化，这个过程会反复运行，所以它是一个实时系统，不是一次性报表。

## 你可以先看懂的几个关键词

- **风险轴**：把风险按不同方向分开看，比如监管、供应链、财务、地缘。
- **事件**：一条被系统识别出来的风险信息。
- **业务影响**：这条风险对企业哪部分有影响。
- **ROI**：投入之后值不值得。
- **沙盘**：用来模拟不同假设下的结果。
- **实时**：数据会持续更新，不是静态页面。

## 一句话总结

这个项目的核心，不是“把很多数据摆出来”，而是“把外部变化翻译成企业能马上看懂的风险提示和行动线索”。

如果你把它当成一条流水线来看，会比较容易理解：

**外部数据进来 -> 系统整理判断 -> 前端展示 -> 用户做决策**
