# 企业风控免疫中枢 — POC核心功能与演示指南

> **赛事背景**：半决赛，10进5，截止日期 2026-05-13
> **赛题方向**：先进制造业出海 × 多智能体驱动 × 外部/内部风险联动
> **Demo形式**：1-2分钟视频，展示"外部风险触发内部预警"端到端闭环

---

## 一、核心叙事定位

### 问题陈述（30秒能讲清楚）

一家中国新能源零部件企业同时向东南亚和欧洲出海。CEO最大的焦虑不是技术，是**永远比风险慢半拍**——等他看到报告，损失已经发生了。

欧盟突然更新CBAM细则：
- 财务总监三天后才发现
- 合规部门一周后才评估完影响
- 等供应链调整方案出来，竞争对手已经抢先完成资质认证

**这不是个例，这是所有出海企业的常态。**

外部世界在实时变化，但企业内部的风险感知是割裂的、滞后的、靠人传递的。

### 系统价值主张（一句话）

> **让企业第一次能和外部世界同频。**
> 外部风险每一次变动，自动传导到企业内部对应业务线，实时预警，不再靠人。

## 二、外部→内部风险传导链（核心逻辑）

```
外部世界（实时）                    企业内部（自动响应）
─────────────────────────────────────────────────────────
欧盟CBAM细则更新        →  合规风险亮红灯 → 出口资质预警
地缘政治紧张（东南亚）   →  供应链中断风险 → 备货/替代商预警
汇率异常波动            →  财务敞口测算   → 利润压缩预警
供应商所在地自然灾害     →  交期延误风险   → 客户交付预警
目标国劳工法变化         →  合规成本上升   → 报价体系预警
```

**传导时效目标**：从外部事件发生 → 企业内部收到预警，**分钟级完成**（对比传统：天级）

## 三、系统核心功能模块

### 模块1：外部风险感知层（External Intelligence）

**功能描述**

基于WorldMonitor已有的全球情报基础设施，实时抓取并处理以下信号源：

| 信号类型 | 数据来源 | 覆盖范围 |
|---------|---------|---------|
| 地缘政治事件 | ACLED、GDELT、UCDP | 冲突、制裁、政策变化 |
| 监管/合规变化 | 500+新闻源RSS | 欧盟、东南亚各国法规 |
| 供应链扰动 | 航运AIS、航班延误 | 港口拥堵、航线中断 |
| 汇率/大宗商品 | Finnhub、Yahoo Finance | 人民币/欧元/东南亚货币 |
| 自然灾害 | FIRMS（NASA卫星火点）| 供应商所在地灾害 |

**技术实现**（基于WorldMonitor现有能力）

- 已有：500+新闻源聚合、ONNX本地ML模型（情感分析、NER命名实体识别）
- 已有：Country Intelligence Index（12维度国家风险评分）
- 已有：跨流关联引擎（军事+经济+灾害信号收敛检测）
- 新增：针对出海企业的**行业专属关键词过滤器**（CBAM、碳关税、新能源、锂电、光伏等）

---

### 模块2：AI风险分类与打标签（Risk Tagging Agent）

**功能描述**

这是多智能体架构中的**第一个Agent**：信息分类Agent。

接收外部情报原始信号，输出结构化风险标签：

```json
{
  "event_id": "evt_20260507_001",
  "raw_text": "欧盟委员会发布CBAM第三阶段实施细则，新增锂电池组件碳足迹申报要求",
  "risk_tags": {
    "category": "regulatory_compliance",
    "severity": "HIGH",
    "region": ["EU"],
    "industry": ["new_energy", "battery"],
    "risk_type": "export_qualification"
  },
  "confidence": 0.91,
  "detected_at": "2026-05-07T09:23:11Z"
}
```

**Agent职责**
- 输入：原始新闻/事件文本
- 处理：NLP分类 + 行业关联判断 + 严重程度评估
- 输出：结构化风险标签 + 置信度分数
- 触发条件：severity=HIGH 或 industry命中企业出海目标市场

**技术实现**
- 基于WorldMonitor已有的`ml.worker.ts`（ONNX MiniLM-L6嵌入模型）
- 新增：出海企业行业词典 + 风险分类规则引擎
- 新增：Claude API调用（复杂事件的语义理解和分类）

### 模块3：内部风险映射引擎（Internal Risk Mapping Agent）

**功能描述**

这是多智能体架构中的**第二个Agent**：映射Agent。

将外部风险标签映射到企业内部具体业务线和风险敞口：

```
外部风险标签                    内部业务映射
─────────────────────────────────────────────────────
category: regulatory_compliance
region: EU                  →  欧洲出口业务线（占营收38%）
industry: battery           →  产品线：锂电池组件BMS系列
risk_type: export_qualification →  风险类型：出口资质/认证
                               →  影响部门：合规部、供应链部、财务部
                               →  预估财务敞口：Q3欧洲订单 ¥2,340万
```

**映射规则配置**（企业可自定义）

```yaml
# 企业风险映射配置示例
company_profile:
  name: "XX新能源零部件有限公司"
  export_markets:
    - region: EU
      revenue_share: 38%
      product_lines: ["BMS", "电芯模组", "储能系统"]
      compliance_certs: ["CE", "CBAM", "RoHS"]
    - region: SEA
      revenue_share: 24%
      product_lines: ["BMS", "充电模组"]
      compliance_certs: ["SIRIM", "SNI"]

risk_mapping_rules:
  - trigger: {category: regulatory_compliance, region: EU}
    internal_impact:
      - dept: compliance
        action: "启动合规自查"
        priority: P1
      - dept: finance
        action: "测算财务敞口"
        priority: P1
      - dept: supply_chain
        action: "评估供应商碳足迹数据"
        priority: P2
```

**Agent职责**
- 输入：结构化风险标签 + 企业配置文件
- 处理：规则匹配 + 影响范围计算 + 财务敞口估算
- 输出：内部预警指令 + 受影响部门列表 + 优先级排序

### 为什么需要多Agent而不是单一系统

| 单一系统的问题 | 多Agent的优势 |
|--------------|-------------|
| 信息抓取和分析耦合，扩展困难 | 每个Agent独立扩展，互不影响 |
| 新增数据源需要改动核心逻辑 | 只需新增抓取Agent |
| 不同行业的分类规则混在一起 | 分类Agent可按行业独立配置 |
| 无法并行处理多个风险事件 | 多个Agent可并行运行 |

## 七、评委常见问题预答

**Q：这和普通的新闻监控有什么区别？**

A：普通新闻监控只告诉你"发生了什么"，我们的系统告诉你"这对你的企业意味着什么"——具体到哪条业务线、哪个部门、多少财务敞口、需要做什么。这是从信息到行动的完整闭环。

**Q：多智能体体现在哪里？**

A：三个Agent分工明确：信息抓取Agent负责多源数据实时监控，风险分类Agent负责NLP理解和标签化，内部映射Agent负责企业个性化的风险传导计算。每个Agent可以独立扩展，比如新增一个行业只需配置新的映射规则，不影响其他Agent。

**Q：数据是真实的吗？**

A：外部风险数据完全真实——WorldMonitor已经在生产环境运行，接入了65+真实数据源。内部企业数据在Demo中使用模拟数据，但映射逻辑和传导链是真实可用的。

**Q：为什么选新能源零部件这个场景？**

A：三个原因：第一，新能源出海是当前最热的先进制造业话题，评委熟悉；第二，欧洲CBAM和东南亚地缘风险并存，可以同时展示系统处理不同类型外部风险的能力；第三，外部→内部的传导链最清晰，最容易在1分钟内讲明白。

**Q：这个系统能推广到其他行业吗？**

A：可以。系统的核心是"外部风险→内部映射"的框架，企业只需要配置自己的出海市场、产品线和风险映射规则。新能源是我们的Demo场景，但同样的框架适用于机械装备、化工材料、消费电子等任何出海制造业。
